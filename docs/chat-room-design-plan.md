| App 標頭 | 白色標頭；橘色只用在按鈕、未讀數、選取。 |

## 目的

為 MasterBox 定一套自己的聊天室樣式。後台網頁和 App 共用同一套規則，所有來源都用這個聊天室：FB、IG、WhatsApp 官方、WhatsApp 掃碼、之後的 LINE，以及 Chat Box 的對內和對外。

流程：

1. 在 Figma 空白畫板畫出畫面，每個畫面附上說明。
2. 跟使用者討論、修改。
3. 定稿後，照設計稿實作[第一階段](unified-chat-phase1.md)。

## 原則

1. **MasterBox 自己的樣式**：參考 WhatsApp 和 FB Inbox 的優點，但外觀用 MasterBox 的品牌，不模仿任何一家。
2. **後台和 App 同一套規則**：區塊名稱、訊息泡泡、圖示、顏色、限制的呈現方式都一樣。版面依螢幕大小調整，行為不變。
3. **基礎固定，加掛依來源**：基礎功能每種來源都有。加掛功能放在固定的位置，來源支援才出現（見[第一階段設計](unified-chat-phase1.md)的功能清單）。
4. **限制有三種，各有固定的呈現方式**：

   | 情況 | 例子 | 呈現 |
   |---|---|---|
   | 來源不支援 | FB 對話不能用範本、客戶對話不能通話 | 不顯示 |
   | 平台規則暫時不允許 | WhatsApp 官方超過 24 小時 | 輸入區上方顯示提示：原因和改用什麼方式 |
   | 使用者權限不夠 | 一般員工不能刪除、看不到沒分配的頻道 | 不顯示；或按鈕停用，滑過或點擊時說明需要管理員 |

5. **一眼看出來源**：每個對話和每則訊息都看得出來自哪裡：FB、IG、WhatsApp 官方、WhatsApp 掃碼，或 Chat Box 的對內、對外。

## 參考

| | FB Inbox（Meta Business Suite） | WhatsApp | MasterBox 的取捨 |
|---|---|---|---|
| 定位 | 商家的客服收件匣 | 個人通訊 | 商家客服加上團隊溝通 |
| 版面 | 三欄：列表、對話、客戶資訊 | 手機上一次一個畫面；桌面兩欄 | 桌面三欄，手機一次一個畫面 |
| 管理功能 | 標籤、指派、備註、狀態、篩選 | 幾乎沒有 | 取 FB Inbox 的做法 |
| 對話體驗 | 比較陽春 | 泡泡、已讀勾勾、引用回覆、表情回應、語音、長按選單 | 取 WhatsApp 的做法 |
| 手機操作 | 一般 | 滑動回覆、長按、底部選單 | 取 WhatsApp 的操作習慣 |

## 各區塊要畫的內容

| 區塊 | 內容 |
|---|---|
| 對話列表項目 | 頭像、名稱、來源標記、最後訊息、時間、未讀數、指派人、狀態、標籤（最多顯示一個） |
| 對話標頭 | 名稱、來源和頻道名稱或電話、指派、狀態；動作按鈕依功能出現：通話、範本、更多 |
| 訊息泡泡 | 文字、圖片、影片、語音、檔案、貼圖、位置、範本訊息、引用回覆、表情回應、送出中、已送出或已讀、失敗加重試、同事回覆標示 |
| 系統訊息 | 日期分隔、指派變更、狀態變更、24 小時期限到期 |
| 輸入區 | 多行文字、表情、快速回覆；加掛位置：附件、範本、語音 |
| 限制提示 | 三種限制各一個樣式（見原則第 4 點） |
| 側欄 | 客戶資訊、標籤、內部備註；Chat Box 對內時改成成員和群組設定 |
| 空白和錯誤狀態 | 沒有頻道、沒有對話、篩選沒有結果、載入失敗、斷線重連中 |
